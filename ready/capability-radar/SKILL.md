# 能力雷达

把「外部工具生态在变什么」持续吸收成「琳 该会什么、Cedar 该不该学/用」。补上能力层唯一缺的链路——**外部→内部的增量引入**：`github-empirical-research` 管存量选型（点名才查），`ai-config-upgrade` 管存量优化（说升级才改），本 skill 管增量引入（主动扫、抓趋势、落行动）。

## 何时用 / 何时不用

| 场景 | 路由 |
|---|---|
| 「最近有什么新工具 / 什么火 / 该不该学」 | → 本 skill |
| 「这几个库选哪个 / 这个库还活跃吗」 | → github-empirical-research |
| 「优化我的 SOUL / 自定义指令 / 记忆」 | → ai-config-upgrade |
| 纯知识点问答 | 直接答 |

## 三条硬规则（违反即返工）

1. **先定靶，再扫描**——不答「GitHub 火什么」这种无靶问题，先问「这次要解决什么、对用户当前目标有没有用」。无靶扫描＝报一堆与用户无关的星数，等于没扫。**靶心以用户当场声明为准，不预设任何固定主线**（DevOps 等职业路线属「打地基学习」，用户未主动提就不往那引）。
2. **扫出候选必过三查实证再下「学/用」结论**——星数/下载量/活跃度/许可证四样查齐（复用 github-empirical-research 的三查）。凭直觉说「这个值得学」＝噪音。
3. **每个候选必须落到「一个动作或一个不动作」**——学/用/跳过三选一，不给「了解一下」这种骑墙。跳过也是结论，且必须记原因（负向决策落盘，防未来重提已否决项）。

## 流程：定靶 → 扫 → 查 → 蒸馏 → 落地

### 第 1 步 · 定靶
- 靶心 = 用户当场声明的目标；用户没声明，就只做「通用工具生态感知」，不往任何特定职业路线（含 DevOps/DevSecOps/CCNA/homelab）上套。
- 一句话写靶：「我要从这次扫描里得到什么决策」。

### 第 2 步 · 扫（拿信号，不拿结论）
- 信号源：GitHub Trending（当日/本周）、`whatstrending.ai/repos`、Hacker News、生态周报（startupcorners 等 digest）。
- 抓：名称、star 数（带采集日期）、单日/单周增量、一句话是干嘛的。
- **大输出先落盘**（`tmp/radar/`），只把候选摘要提进对话。

### 第 3 步 · 查（三查实证）
- 复用 github-empirical-research 的「体量/活跃/形态」三查 +「收费吗/谁已占位」两问。
- 只对「过了靶」的候选深查，噪音项直接跳过。

### 第 4 步 · 蒸馏（出趋势，不是出清单）
- 不只报「哪些火的」，还要答「这波变化说明什么」——例如 2026-10 的信号是「火的不是模型，是 agent 周边（技能库/记忆/harness）」。
- 趋势必须落到 Cedar 身上：这波对他意味着什么（机会/威胁/无关）。

### 第 5 步 · 落地（一个动作）
- 每个候选出裁决：✅学 / ✅用（搬进能力层）/ ⏭跳过。
- 「搬进能力层」的候选 → 转 `skill-dev` 走立项，别当场写 skill。
- 「跳过」记原因，写进对应记忆（负向决策落盘）。

## 输出模板

```
## 趋势（一句话：这波在发生什么）
## 候选（表格：名称/体量/增量/活跃/许可/裁定）
## 对你意味着什么（机会·威胁·无关）
## 一个动作（学/用/跳过 + 下一步具体命令或路径）
## 依据与时效（数据采集时间；失效条件）
```

## 反模式（交付前自检）

- ✗ 无靶扫描，报一堆与主线无关的星数。
- ✗ 扫完不下裁定，甩一张清单让用户自己挑。
- ✗ 凭「星数高」直接说「值得学」，没查活跃度/许可/收费。
- ✗ 把「搬进能力层」直接写成 skill，跳过 skill-dev 立项（没失败测试的 skill＝未测代码）。
- ✗ 「跳过」不记原因，导致未来会话重提已否决项。

## 失效条件

- 网络端点变化 → 换源并更新第 2 步信号源表。
- 主线变化（Cedar 换方向）→ 同步更新第 1 步靶心。
- 连续两周无调用 → 评估并入 github-empirical-research，不单独维护。
