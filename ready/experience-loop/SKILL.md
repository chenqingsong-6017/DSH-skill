# 经验循环（Experience Loop）

> **版本轨迹**：见文末「沿革」表与 `references/沿革.md`。
> ⚠ **历史版本号不在此并列**——各 `SKILL.md` 的 `version` 字段是**唯一权威源**
> （此处曾留一份停在 2.1.0 的快照，与文末沿革表自相矛盾，2026-10-05 按 2.5.0 清理为指针）。

## 三段式总览（先读这一节）

本机制按**任务生命周期**运行，不是按口令清单：

| 段 | 何时用 | 做什么 | 旧版对应 |
|---|---|---|---|
| **① 立架构** | 新建工作区（或改造既有工作区） | 探载体 → 建骨架 → **当场立归档契约** | 模式A ＋ 模式D 第4步 |
| **② 建任务** | 每次新任务，**自动执行** | 建任务文件夹 → 检索经验卡 ≤3 → 方案研讨闸门 | 模式R ＋ 闸门G |
| **③ 沉淀复用** | 任务收尾（说「**项目收尾**」即指**本会话任务**收尾），或**过程中** | 筛做法 → 写卡 → 更新索引 → 写回执 | 模式B |
| 维护 | 低频，用户主动发起 | 归并经验库 ／ 整理归档 ／ 清理冗余 ／ **升级工作区** | 模式C ＋ 模式D |

> **本技能的附件（按需读，不要全读）**：`references/立架构.md`（新建或改造工作区时）｜
> `references/维护.md`（归并／整理清理／升格下沉／记忆体检／效果体检／语义盲评／**版本对齐**触发时）｜
> `references/沿革.md`（**追溯某条规则的由来／某个坑踩过几次**时）｜`assets/清理手册.md`（执行整理清理时）｜
> `assets/产出物分类.py`（**判「这是什么」**：`report` 只读对账；`quarantine-list [--commit]` 出隔离区 `_按类型清单.md`；
> `folder-lists [--commit]` 为每个任务／主题文件夹出 `_类型清单.md`——**类型的可见形态**）｜
> `assets/回执统计.py`（**判升格阈值前必跑**，dry-run 默认；`--workspaces` 出**全仓制式与同号跨区视图**；
> 2.5.0 起出「机械证据覆盖率」＝ `·闸`÷已评，并把「待修订」拆成「定性／提示」两档；

> 3.4.0 起**自动识别挂载制**〔描述性卡名——编号制优先、0 行才启用；无「等级」列时相关检查**明示不适用**〕）｜

## 通用原则：先继承，再新建

任何一段落地前，先读 `~/.workbuddy/MEMORY.md` 与本工作区 `.workbuddy/memory/MEMORY.md`，
把用户**已有约定**（聚合方式、命名惯例、目录分工、既有载体）继承进来，
**只在没有约定的地方才给默认值**。**文件不存在就跳过、不报错**——新工作区常常还没有工作区级 MEMORY。

**读完顺手判一次「归属」，只报不改** —— 这是双向通道的**天然相遇点，零额外触发词**：
- 读到某条**只跟某类任务有关**的常驻记忆（参数、字段清单、某 skill 的操作细则）→ 按下方
  「升格与下沉」的下沉判据，提示用户"这条可以搬去 X"。
- 读到某张**已经够通用**的经验卡 → 按升格判据提示可升格。
- **只提示，绝不动手** —— 任何搬移都要用户点头。

> 这是本机制最容易出错的地方：模板驱动的"标准化"会把工作区里已经自洽的体系
> 变成两套并行、互相打架的东西。

## 工作区结构

```
工作区/
├── 任务/                    ← 每个新任务一个子文件夹（见「② 任务文件夹规范」）
│   └── YYYY-MM-DD_主题/
│       ├── _说明.md         ← 下划线开头排最前：任务一句话、产出清单、关联经验卡
│       ├── _方案.md         ← 研讨闸门定案后的基线；落地与返工对照它
│       ├── 产出文件…        ← 交付物平铺在根层，用语义化中文文件名
│       └── data/  scripts/  ← 文件多时才建
├── 经验库/
│   ├── _索引.md          ← 唯一入口，一行一条；禁止全量读取经验卡目录
│   ├── 方法论/ 避坑/ 素材/  ← 经验卡（E-XXX.md），等级分 草稿／验证／★核心／已升格／已去重／已失效
│   ├── _台账.md          ← 【3.0.0 三合一】待升格／待修订／盘点三类落点共用一份（手工维护）
│   ├── _载体总表.md      ← 【2.4.0】已升格/已去重卡 → 载体；**派生视图**，由盘点脚本生成
│   └── 校准台账.md       ← 【可选第 4 类】仅预测型/判断型工作区才建
├── 复用回执/YYYY-MM.md   ← 每次复用的效果记录（✓/△/✗，2.5.0 起带 ·闸／·评 来源后缀）
├── ARCHIVE.md            ← 归档契约：目录树＋路由表＋命名规范（① 第 3 步生成）
├── _隔离区/YYYY-MM-DD/   ← 待删文件的暂存地，保留 30 天
└── .workbuddy/archive/   ← 迁移日志／删除日志（回滚凭据，非产物）
```

> ⭐ **同级配套文件**（均**非经验卡**）：`_台账.md`（【3.0.0】三类落点合一——待升格＝达阈待批、
> 待修订＝判出待改、盘点＝索引↔载体对账凭据；**手工维护**）、
> `_载体总表.md`（**派生视图**，由盘点脚本生成、**不手写**）。

> **本结构是默认形态，不是强制形态。** 若工作区已按项目 / 标的 / 客户 / 站点 / 产品线等领域轴
> 建好文件夹，**保留既有轴**——只把机制目录挂在根层，`任务/` 退化为「非领域类一次性任务」的归口。
> 若已有手册 / 规范 / 台账 / 经验库这类载体，走**挂载**而非另立一套。

模板见 `assets/经验卡模板.md`、`assets/索引模板.md`、`assets/回执模板.md`、`assets/台账模板.md`、`assets/归档规则模板.md`；
整理与清理的完整操作细节见 `assets/清理手册.md`（本文只留判据与路由）。

## ① 立架构（新建工作区／改造既有工作区）

> 完整流程见 `references/立架构.md`（新建或改造工作区时必读，不要凭本摘要执行）。
> 骨架：**第 0 步先探测**（有没有既有载体？日期型／领域聚合型／**吸收型**？有无既有规则文件）→ **第 1 步建骨架**
> （**吸收型另加常驻输入区**，如 `前沿情报/YYYY-MM/`）→ **第 2 步可选机制按需增列**（校准台账仅预测型；清理安全层仅做清理时）
> → 第 3 步当场立 `ARCHIVE.md` → **第 4 步首批入库**（既有成果多时抽卡，否则索引是空的）→ **第 5 步告知用户机制已就绪**。
> 一句话判据：**新机制与既有目录语义重叠 → 走挂载，不新建**；领域聚合型的既有文件夹一律不动。
> ⚠ **吸收型的头号死因是「只进不出」**：建输入区**必须同时定义转化出口**（谁消化、消化成什么），定义不了就别建。

## ② 建任务（每次任务，自动执行，不向用户索要指令）

**第 0 行（硬闸，不可跳过）**：动任何工具之前——读文件、跑脚本、写文件都算——先读 `经验库/_索引.md`，
并在**回复的第一句**写出检索结论：`本次复用 E-00X…` 或 `本次未匹配到可复用经验`。

同一次动作里当场落一行痕（2.2.0 新增）：把结论写进 `任务/<主题>/_说明.md` 的「**关联经验卡**」行——
`命中：E-012、E-009` 或 `未匹配（已读索引）`。
**为什么必须落盘**：「第一句声明」只活在对话里、**不留物证** ⇒ 漏检数只能靠自评、真实值必然更高
（2026-10-03 实测：**连诊断这个环节的会话自己都漏检了**）。落盘后**从自证变他证**，
收尾／归并／效果体检都能机械核查。**零新增文件**——② 段第 5 条已要求开工即建任务文件夹，
那一刻 `_说明.md` 一定存在。

**「没搜到」可以说，「没搜」不可以说。** 收尾才补检索＝**漏检**（实测已发生多次）——
漏检比不检索更危险：它让人以为复核已经做过了。
**边界（2.2.0 起改为可机械判断）**：**建了任务文件夹 ＝ 非琐碎 ＝ 必须留检索痕迹**。
纯问答、不产生文件的任务**不建文件夹**，也就不留痕——**边界跟着文件夹走，不靠自我判断**。

1. **先定位本区的经验库索引**（2.2.1 修判据）：默认 `经验库/_索引.md`；**挂载型工作区按既有命名**
   （如 `_经验库/_索引.md`，可查其 `README_目录组织规则.md`／`ARCHIVE.md`／`README.md`）。
   两处都没有才跳过本段，不要主动初始化。
   ⚠ **为什么不能只认默认名**：① 段明确允许「**有则挂载而非新建、保留既有命名**」；
   若闸门只认 `经验库/_索引.md`，挂载型区会被按字面判成"无索引"⇒ 每一轮都合法跳过检索
   （实测：某挂载型工作区索引在 `_经验库/_索引.md`，其回执绝大多数行填 `—`）。
2. 只读 `_索引.md`，按当前任务关键词匹配，选 **≤3 条**；只读这几张卡的详情。
   - **匹配不上就明说**：回复里写一句「本次未匹配到可复用经验」，**禁止**用"意思差不多"的卡凑数。
     硬凑一张不相干的卡比不检索更糟——它会让结论悄悄跑偏，且不报错。
   - **索引关键词怎么写**：用**任务类型词 ＋ 场景词**（如「外部报送报告审核」「送审稿数字勾稽」），
     不用抽象词（「注意」「加强」「细节」）——抽象词匹配不上任何具体任务。
3. 若复用了卡片，回复开头用一句话说明用了哪几张（如「本次复用 E-012、E-018」）；
   没有匹配则**明说不匹配**，不打扰。
4. 引用卡片内容时用路径引用（`见 经验库/方法论/E-012.md`），不重复粘贴正文；
   同一会话已读过的卡不得重读。
5. **开工即建任务文件夹**：`任务/YYYY-MM-DD_主题/`（主题为 ≤10 字动宾短语），
   **并在 `_说明.md` 的「关联经验卡」行写下第 0 行的检索结论**（`命中：…`／`未匹配（已读索引）`）。
   这一步与建文件夹是**同一个动作**，不许事后补。纯问答、不产生文件的任务不建文件夹。
6. 任务交付前，向 `复用回执/YYYY-MM.md` 追加一行：
   `| 日期 | 任务 | 卡片ID | ✓/△/✗ | 检索 | 方案闸 | 新证据 | 备注 |`。文件不存在则按 `assets/回执模板.md` 创建。
   - **两列分开记**（2.2.0 拆分）——它们本是两套成本模型的账，挤在一列必然互相污染：
     **「检索」**（本任务开工时有没有读索引、读到了什么）：`命中 E-0XX,…`／`未匹配`／`漏检`／`未涉及`；
     **「方案闸」**（闸门G 过几轮）：`过1轮`／`过2轮`／`直通`／`用户跳过`／`无人值守`／`未涉及`。
     ⚠ 旧单列里的 `用户跳过` **指的是方案研讨被跳过，与检索无关**——这正是必须拆列的原因。
   - **值域封闭，不许写散文**（如 `—`）：写散文等于这行没有信息；"未涉及"只能写 `未涉及`。
   - ⭐ **快速行（3.0.0）**：当「检索」＝`未涉及` **且**「方案闸」＝`未涉及` 时（纯问答／小任务），
     备注列**只写任务一句话**即可，其余列照填枚举值、**免除解释义务**——
     **列不合并、值域不新增**：减的是写字成本，不是信息。
   - **「新证据」必须指名卡号**（2.2.2）：写 `有：E-0XX`（多张逗号分隔）或 `无`。
     **一行常记多张卡**，只写一个 `有` 会让脚本**把它算给同行的每一张卡** ⇒ **假阳性达阈**
     （实测：某卡 3 次复用里 2 次"新证据"全来自同行其他卡，它的达阈是假的）。
     **只为真正带回新证据的那张卡写 `有：`**，其余卡这行就是没有新证据。
     旧行只写 `有` 的仍按粗口径算、输出标 `（粗）`——**这类历史达阈一律人工复核**。
   - **漏检自检**：若开工时**没有**声明检索结论（收尾才补、或根本没检索），「检索」列填 `漏检`，
     备注写清"开工未检索、收尾补 E-00X"。**漏检必须留痕**——它是唯一能被统计的机制失效信号。
   - 交付前可跑 `assets/检索痕迹检查.py` 自检：任务文件夹缺检索痕迹会被逐个列出。

### 闸门G：方案研讨（**分级触发**；方向性任务必过，其余直通）

**目的**：把「返工最贵的一步」前移到开工前——先在对话里敲定方向、交付物、边界、方案选项，
批复后再落成品。直接出成品→多轮改→返工，是烧 token 又跑偏的根源。

**触发时机**：建好任务文件夹之后、任何成品落地之前。纯问答不触发。

⭐ **分级判据**（3.0.0 新增：先判该不该过闸，再决定过不过）——**满足任一条件才过闸，否则直通**：

1. 交付物是**新类型**（本区没产出过的形态）；
2. 预期产出 **≥3 个文件**，或跨多个环节；
3. 有**外部接收方**（报送、交付他人使用）；
4. 需求一句话说不完，或含「可能／或者／看看」等不确定词。

直通任务在回执「方案闸」列填 `直通`（值域已有，无需新增枚举）。
**判据全部可机械判断**（数文件、看交付物形态、看用词），**不留自由裁量**——
闸门的价值在于前移返工成本，对无方向性的任务，过闸本身就是净成本。
（回测依据：若直通率 <30%，说明判据太松，先收紧第 4 条。）

⭐ **与 `沙盘推演` 的衔接**（2026-10-15）：任务**已过沙盘推演**（有推演卡）的，**推演卡直接充当研讨卡**——按下面五段格式从推演卡取材落 `_方案.md`，**不重出研讨卡**；回执「方案闸」列记 `过闸（推演卡）`。两条闸**过其一即可，不叠加**（分工：本闸＝自动轻量；沙盘推演＝显式深度）。

1. 产出**研讨卡**（对话内、一屏内、**≤20 行**，禁止写成长篇方案书），固定五段：
   ① **目标**——一句话复述"你要的成果是什么"，请用户确认理解没偏；
   ② **交付物**——拟产出文件名 ＋ 形态 ＋ **给谁用**；
   ③ **前提与边界**——只列阻塞项：工具边界／使用者范围／数据共享／时间人力；没相关的写「无」；
   ④ **方案选项**——2–3 个可行做法，每个一句取舍，**标注推荐项**；
   ⑤ **待拍板**——**≤3 个**必须用户定的问题；其余用推荐默认值，不拿来问。
2. **停下等批复**——不继续做成品。用户可能：选某个方案／回答待拍板项／提出修正。
3. 按批复更新成**定案版**，写入任务文件夹 `_方案.md`（**≤20 行**；无方向性变更的可只写 3 行摘要）。
4. 进入落地：严格对照 `_方案.md` 执行。
5. 出现**方向性变更**（换交付物、扩边界、改路线）→ **回到本闸门**：重出研讨卡 → 批复 →
   就地更新 `_方案.md` 并在顶部加 v2/v3 变更记录，不另起炉灶。
   基线内的小调整（措辞、细节）不必回闸门。
6. **过闸即记账**：把本任务的过闸结果写进 `复用回执` 的「**方案闸**」列（格式见 §② 第 6 条）——
   只记「几轮／直通／跳过」一个词，不写过程。没有这本账，闸门值不值得就一直无从判断。
7. **无人值守豁免**：定时任务／自动化会话没有用户在场，「停下等批复」会一路卡到超时。此类任务**不过闸门**：
   按推荐默认值直接落地，交付物开头标注「**未过闸门G，按默认方案执行**」，回执「**方案闸**」列填 `无人值守`。
   ——**豁免也要记账**，可观测性不破。

**Token 纪律**：研讨卡与 `_方案.md` 各 ≤20 行；研讨阶段**不产生任何成品文件**；
同一方向性问题不得重复研讨两轮以上，已拍板的点不再问。

## ③ 沉淀复用（用户触发：「项目经验沉淀」／「项目收尾」）

### 收尾档（任务已完成／告一段落）

2. 先读 `_索引.md` 判重：有相近卡则**合并修订**该卡（**其复用次数不变**——按 `E-011` 案例两分法，

3. 新卡按 `assets/经验卡模板.md` 编写，**正文 ≤500 中文字**，编号沿用最大 ID 递增，

   ⚠ **卡内不记「复用次数」**（2.4.1 起）：次数只由 `assets/回执统计.py` 从**回执聚合**、落索引「复用」列。
4. 在 `_索引.md` 追加或更新一行，每条 ≤40 字。
5. 若本次任务有任务文件夹，在其 `_说明.md` 的「关联经验卡」行**补上新卡 ID**

6. **收工必报（硬要求）**：在回复里列出——**入库了哪些**（卡号／文件名）＋ **每条一句话理由**
   （凭什么值得留）。**一次任务 0–3 张卡；没有可沉淀的就明说"本次无可沉淀"**，不硬凑。
   - **用户保留否决权 —— 不否定即代表没意见**；被否决的当场处置（撤回／改标），**不争辩**。
   - ⚠ 分界：**本工作区内的沉淀由 AI 决定；"是否进全局规则"一律由用户说了算**（见全局规则「经验沉淀分工」）。

     「**本轮有无卡达升格阈值**」，**没有也写一句"本轮无"**。

     达阈但未获批准的 → 录进 `经验库/_台账.md`（类型＝待升格；见「升格 ↔ 下沉 · 悬挂台账」）。

### 快记档（任务进行中，说一句就继续干活）

任务没结束、但踩到了值得记的坑或定了口径时用：

- **只记一条**，进对应目录但**等级标「草稿」**，索引同步加一行标「草稿」。
- **不做**：`_说明.md` 回填、写复用回执、判重合并——这些留到收尾档。

## Token 纪律（所有段落必须遵守）

- 任何一段不得全量读取经验卡目录；**唯一入口是 `_索引.md`**。
- **单卡 ≤500 中文字**（按中文字符计，不含 markdown 语法）；索引每条 ≤40 字；
  索引超 100 条时按目录拆分为 `_索引_方法论.md` 等二级索引。
- 同一任务链内，已加载的经验卡只以路径引用复用，禁止重复粘贴正文。
- 整理清理段：文件清单 JSON 只由脚本消费，**禁止整份读进对话**；
  只读脚本打印的统计与 Top 表，大目录先用汇总数字判断值不值得继续。
- **触发词增删必须同步本文件 frontmatter 的 `description_zh`／`description_en`／`description`
  三处**，并实测长度——⚠ **两个不同的上限**：**中文描述 500 字符**、**英文描述 1000 字符**
  （2026-10-09 实测报错原文：「Skill 中文描述：当前 518 字，上限 500 字」；
  此前误记为"三者均 1000"，`description_zh` 因此被放行到 518）。
  **量的是 YAML 解析后的生效值**，不是文本长度；`description_en` 是 1000 档的超限高发字段
  （中文写惯再翻译成英文极易膨胀到 1500＋）。
