# 附：① 立架构 全流程

> `experience-loop` 的**按需附件**——**新建工作区或改造既有工作区时必读**（SKILL.md 只留骨架摘要）。
> 本文件自 v1.4.2 从 SKILL.md 迁出；此后随机制迭代（最新：**3.2.0 并入「吸收型工作区」形态**）。

## ① 立架构（新建工作区／改造既有工作区）

### 第 0 步 · 先探测，别急着建

这一步决定后面全部动作的形态，**只读、禁止写任何文件**：

1. 有没有**既有的方法论载体**——手册、规范、SOP、台账、已有经验库目录？
2. 工作区是**日期型**（文件按时间产生、彼此独立）还是**领域聚合型**（按项目／标的／客户／站点聚合）？
3. 根层有没有**既有机制目录与规则文件**（`_` 前缀目录、`README_xxx规则.md`）？
4. 它是**产出型**（把事做完、交出文件）还是**吸收型**（持续接收外部输入——资讯／论文／行情／政策——再转化为自己的判断）？

| 探测结果 | 走哪条路 |
|---|---|
| 没有既有载体 | **新建**：按第 1 步建标准骨架 |
| 已有载体 | **挂载**：把经验库定位成既有载体的**待验证缓冲区 ＋ 操作层** |
| 已有归档规则文件 | **不建** `ARCHIVE.md`，沿用既有规则文件 |
| 领域聚合型 | 既有项目文件夹**一律不动**；`任务/` 只承接不绑领域的一次性任务 |
| **吸收型** | 骨架增设**常驻输入区**（如 `前沿情报/YYYY-MM/`）：**周期性产出按时间归档、不进 `任务/`**；⚠ **建区时必须同时定义转化出口**（见下），定义不了就不要建输入区 |
| **老版本工作区**（无「架构版本」标记、机制形态旧） | **不暴力重排**：先按 `维护.md`「版本对齐」跑特征对账，**只补缺、不追平** |

> ⭐ **吸收型的头号死因是「只进不出」**（2026-10-09 实测于一个吸收型工作区）：
> 输入区每周稳定产出，却没有任何环节把它消化成自己的判断 —— 几个月后它就是一摞没人看的链接。
> **故「吸收型」这一路必须成对交付两件东西**：① **常驻输入区**；② **转化出口**。
> 出口在 `ARCHIVE.md` 里写成**可执行的三步判据**（例：周期产出 → 输入区；外部知识 → 主题库、
> 自己的做法 → 经验库；只有"会改变做事方式"的才准入库），并把「**周期产出 vs 一次性任务**」
> 列为**路由表第一条判据**—— 否则周期产出会持续污染 `任务/`，把它变成一条时间线。

**挂载路径怎么补**：把默认机制逐项与既有体系对照列一张「机制／现状／缺不缺」表，
**只补确实缺的，不补"看起来应该有"的**。实测案例：某成熟工作区 13 项默认机制中只有 3 项真缺。
判据：新机制名与既有目录**语义重叠** → 走挂载，不新建。

注意：硬改既有目录名会打断脚本里的相对路径依赖，且**静默失效、不报错**——
"统一整齐"的收益远低于断链的风险。既有卡片的**编号体系与文件名格式一并继承**
（既有用描述性中文名，就不要改成 E-XXX）。

### 第 1 步 · 建骨架（两条路径都要）

`任务/`、`经验库/{方法论,避坑,素材}/`、`经验库/_索引.md`（用 `assets/索引模板.md`；⚠ **首列必须是纯文本 ID、勿用 markdown 链接**，否则盘点脚本读不到数据行——见模板内说明）、`复用回执/`。

**吸收型再加一层**：常驻输入区 `<输入源>/YYYY-MM/`（名字按内容定，如 `前沿情报/`、`外部论文/`），
并在该目录放一份 `_说明.md`——写明**产出节奏、固定结构、纪律（去重／分级／准入）**，
让每次自动产出都照同一格式落，而不是每期一个样子。
⚠ **只建当月，不预建未来月份**；子目录按需创建，不预建空壳。

### 第 2 步 · 可选机制按需增列

- **校准台账**（仅**预测型／判断型**工作区）：`经验库/校准台账.md`，一行一条
  「对象／预测内容／预测日／到期日／结果／归因」，用于统计**判据命中率**并反哺判据权重。
  **没有预测场景就不要建**，避免留空表。小样本（≤1 例）不构成统计，命中率列写「样本不足」。
- **台账**（**建议都建**；**3.0.0 起三类合一**）：`经验库/_台账.md` —— **待升格／待修订／盘点三类共用一份**。
  盘点类的行记「上次全量盘点日／卡片数／Missing·Orphan·Stale 数／发现项／处理状态／明细报告」，
  它让「**定期**」**不靠记性**——该日期是「记忆体检／归并」的**第一步硬闸**
  （距今 >30 天，或卡片数增量 >10 ⇒ 先跑全量盘点，再干别的）。
  格式见 `assets/台账模板.md`；跑 `assets/索引一致性检查.py`（**只读**）。
- **载体总表**（**建议都建**，2.4.0 新增）：`经验库/_载体总表.md`，列「已升格／已去重卡 → 载体」。
  **它是派生视图、不要手写**——由盘点脚本 `--carriers --carriers-out` 直接生成。
  回答「这条已升格的知识现在住在哪个载体里」（原先只能靠读散文 ＋ 人肉搜）。
  格式见 `assets/载体总表模板.md`；**知识搬迁后重新生成**。
- **清理安全层**（会做文件清理才建）：`_隔离区/`、`.workbuddy/archive/`。见 `assets/清理手册.md`。

### 第 3 步 · 当场立下归档契约

在 `ARCHIVE.md` 落盘（用 `assets/归档规则模板.md`），固定**五段**：
**目录树**（放什么／不放什么）、**路由表**（哪类文件 → 哪个目录）、**类型表**（产出物类型体系，值域封闭）、
**命名规范**、**生命周期**。
> 落位是**两步**：先判「**这是什么**」（类型表）→ 再判「**该去哪**」（路由表）。
> ⚠ **吸收型**：路由表的**第一条判据**必须是「**周期产出 → 输入区**；一次性任务 → `任务/`」，
> 第二条是「**外部知识 → 主题库**；自己的做法 → 经验库」—— 这两条是吸收型不变成垃圾场的护栏。

生成时**先读全局与工作区 MEMORY，把既有约定继承进来**，只在没约定的地方给默认值。
**顶部写入「架构版本」行**（`架构版本：对齐 experience-loop v<版本>（YYYY-MM-DD）`）——
它是"这份契约属于哪一版"的锚点，日后「版本对齐」与技能升级都读它；**技能改版后在此更新**。
生成后向用户复述路由表要点，并在工作区 MEMORY.md 补一行指针（一句话 ＋ 路径），
否则下次仍会走老路。

> 与旧版的差别：原「模式D 第4步」要求先做完整理才立规则；现在**建区时就立**，
> 之后的文件从一开始就有位可放。

### 第 4 步 · 首批入库

若工作区已有大量既有成果（历史报告、结论、摘要），**顺手抽首批卡片**——
这是唯一允许超过常规「0–3 张」上限的场合。否则索引是空的、② 检索不到任何东西。
抽卡前先读 `_索引.md` 判重。

### 第 5 步 · 告知用户机制已就绪

新任务会自动建文件夹并复用经验；方向性任务默认先出研讨卡定案再落地（说「直接做」可跳过）；
说「**项目经验沉淀**」或「**项目收尾**」（＝**本会话任务**收尾，非整项目结束）触发沉淀；说「整理工作区」「清理冗余」触发整理归档
（先出只读报告、经批准才动手，删除先进 30 天隔离区）；
说「立归档规则」触发生成／更新 `ARCHIVE.md`；
说「**记忆体检**」触发**盘点（对账索引↔载体）＋ 双向清单**（**只报不改**）。

**吸收型另须告知**（否则输入区等于只写不读的日志）：① 输入区的产出**怎么转化**成方法论（出口三步判据）；
② 消化动作是**手动触发**（如按月把候选过一遍）还是**另设定时任务**；③ 转化结果落 `经验库/`（做法）或
`主题库/`（知识），**不落回输入区**。
