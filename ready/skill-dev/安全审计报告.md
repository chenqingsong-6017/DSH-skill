**5.2 ⚠️ BUG-1（中）：传 `.` 时 `NAME_DIR` 误报 FAIL**

```python
# skill_check.py:97
dir_name = skill_dir.name      # Path('.').name == ''
# → name「skill-dev」与目录名「」不一致（规范硬性要求）
```

**实测**：
```
$ cd skill-dev && python scripts/skill_check.py .
  [FAIL] NAME_DIR  name「skill-dev」与目录名「」不一致（规范硬性要求）
  结果: 12 PASS / 1 WARN / 1 FAIL
$ python scripts/skill_check.py C:/Users/.../skills/skill-dev
  [PASS] NAME_DIR  name 与目录名一致
```

- **危害**：在 skill 目录内用 `.` 调用（**最自然的调用方式**）必然产生一个无法豁免的假 FAIL，直接阻断交付门禁。而 `SKILL.md:151` 给出的示例命令正是 `python scripts/skill_check.py <skill目录>`，未提示须用绝对路径——**文档与缺陷叠加会误导用户**。
- **修复**：`dir_name = skill_dir.resolve().name`。

**5.3 ⚠️ BUG-2（中）：中文词数被系统性低估约 3 倍，`BODY_WORDS` 门禁对中文失效**

```python
# skill_check.py:136
words = len(re.findall(r'\S+', body))   # 中文无空格 → 整段连续汉字记作 1「词」
```

**实测数据**（本 skill 自身 `SKILL.md` 正文）：

| 计量方式 | 数值 |
|---|---|
| 脚本报告（`\S+`） | **904 词** |
| 实际 CJK 汉字数 | **2,798 字** |
| 非空白字符总数 | 5,726 |
| CJK 近似 token（1 字 ≈ 1 token 保守估） | **约 2,800–3,500 token** |

- **偏差**：脚本值 ≈ 真实 token 的 **1/3**。
- **后果**：`BODY_WORDS` 的 FAIL 阈值是 3000「词」，对中文 skill 而言等价于约 **9,000 汉字 / 9,000+ token** 才触发——而规范硬上限是 **5,000 token**。即**一个 token 严重超标的中文 skill 会被判为 PASS**（本 skill 实测 904「词」甚至只落在 500 词 WARN 线上方一点，看起来"还行"，实则已接近预算一半）。
- **连带**：`references/skill-templates.md:159` 教用户「写完后 `wc -w` 核对」——`wc -w` 同样按空格分词，对中文**同样失效**。缺陷从脚本蔓延到教学。
- **修复**：按 CJK 与非 CJK 分别计量，如
  `tokens ≈ len(cjk_chars) * 1.0 + len(re.findall(r'[A-Za-z0-9]+', body)) * 1.3`，
  并同步修正模板中的 `wc -w` 建议。

**5.4 🔵 BUG-3（低）：非 UTF-8 输入抛出未捕获异常**

`skill_check.py:213` `read_text(encoding='utf-8')` 无 `errors=` 兜底、无 try/except。

**实测**：GBK 编码的 SKILL.md → `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xd6 in position 53`，`rc=1`，**输出 traceback 而非可读错误**。
（副作用：rc=1 恰好等于 FAIL，CI 会正确阻断，但用户看到的是 Python 堆栈，无法定位问题。）
**修复**：`read_text(encoding='utf-8', errors='replace')` 并捕获异常输出「文件非 UTF-8 编码，请先转码」。

**5.5 🔵 BUG-4（低）：引用校验不匹配反斜杠路径**

`skill_check.py:156` 正则只匹配正斜杠：`(?:scripts|references|assets)/[\w./\-一-鿿~*?]+`

**修复**：字符集补 `\\`，或先做 `text.replace('\\','/')` 归一化。

**判定**：D5 = 🔵 安全（无可利用攻击面）＋ ⚠️ 2 项功能缺陷需修复。

## 五、结论

### 定级：**Benign（良性，可放行）**

**核心判定**：`skill-dev` 是一个**设计良好、来源扎实、编写诚实的安全工程类元技能**，不含任何恶意意图或可利用攻击面。

**支撑证据（均为实证，非推断）**：

1. **零攻击面**：唯一可执行资产 `scripts/skill_check.py` 仅导入 `re`/`sys`/`pathlib` 三个标准库，**无 shell 执行、无 eval/exec、无网络、无文件写入、无删除**，单次只读目标 `SKILL.md`，行为纯函数式。
2. **零权限索取**：frontmatter 仅有 `name` + `description`，**未声明任何 `allowed-tools`**——比它自己写的「最小化」要求更严。
3. **零外泄链**：无网络出口、无凭证读取、无「读敏感文件 + 联网发送」组合；零宽字符与 BiDi 隐藏字符扫描 **0 处**。
4. **注入命中全部为自我命中**：6 处注入/攻击模式词汇经逐条上下文判定，全部落在**检测正则定义、审计清单条目、攻击手法引用**三类位置，无一为可执行指令。反向看，本 skill 的核心功能之一正是**教人识别并阻断这些攻击**。
5. **来源可信**：约 80 个外部 URL 以 Anthropic 官方域、agentskills.io、OWASP、Snyk、官方 GitHub 仓库等一手来源为主，且**每个都标注了可信度星级**，二手来源明确标 ★/★★。
6. **诚实边界到位**：主动声明数据时效（"2026-02 快照，引用前请复核"）、主动声明能力边界（"静态脚本只查形式与已知危险模式，不查语义正确性"），符合其自身倡导的工程原则。

### 需要处理的问题

**无安全性问题。以下 4 项均为工具可靠性与一致性缺陷，不阻断使用，建议修复后交付：**

1. **GAP-1**（优先）— `skill_check.py` 只扫描 `SKILL.md`。实测用它审本目录会输出「无外部 URL」，而 `references/` 下实有约 80 个。作为安全门禁存在实质性覆盖盲区。
2. **GAP-2**（优先）— 文档承诺扫描 9 类危险模式，脚本仅实现 5 类，缺「编码后执行（base64+eval）」「伪合规话术」「隐藏 unicode 字符」「路径穿越」4 类，其中前两类是本 skill 调研材料亲自点名的高频攻击手法。
3. **BUG-2** — 正文长度门禁对中文失效：`\S+` 分词使中文词数被低估约 3 倍（实测正文 2,798 汉字 ≈ 2,800–3,500 token，脚本报 904「词」）。需按 CJK 单独计量，并同步修正 `skill-templates.md` 中「用 `wc -w` 核对」的教学建议。
4. **BUG-1** — 在 skill 目录内用 `python scripts/skill_check.py .` 调用会因 `Path('.').name` 为空串而误报 `NAME_DIR` FAIL。改用 `.resolve().name` 即可。

**低优先级**：INFO-2（非 UTF-8 崩溃）、INFO-3（反斜杠引用漏检）、INFO-1（存在性探测加固）、INFO-4（第三方镜像来源）。

### 一句话总结

> **这个 skill 是「教人做安全审计」的工具，它自己经得起安全审计——但它的自检脚本存在覆盖盲区（只扫 SKILL.md）与中文计量缺陷，说到的九类危险模式只做了五类。安全上 Benign，工具一致性上待补。**
