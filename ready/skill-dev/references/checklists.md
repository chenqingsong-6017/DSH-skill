# 检查清单库

> 四份清单：立项（Phase 0）｜构建（Phase 3）｜验证（Phase 4）｜发布（Phase 5）。
> 每份都是「能打勾」的判据，不是原则陈述。打不了勾的项等于没定义完。

---

## 清单 A · 立项裁决（Phase 0）

**该造的四个信号**（≥2 个命中才继续）：
- [ ] 这个做法你/团队会**跨项目重复用**（不是一次性方案）
- [ ] 基座模型**不做或做不好**——有可观察的失败证据，不是「感觉它不懂」
- [ ] 需要**多步决策**或**团队约定**，而非模型已知的事实
- [ ] 别人也会受益，值得分发

**不该造的四类**（命中即停）：
- [ ] ❌ 一次性解决方案
- [ ] ❌ 别处已有良好文档的标准实践（模型训练语料里大概率有）
- [ ] ❌ 项目专属约定（应放项目 instructions 文件，不是 skill）
- [ ] ❌ 能用正则/脚本机械校验的约束（做成校验脚本，写文档是浪费）

**增量假设（必须写成一句可证伪的话）**：
> 「在 [场景] 下，没有此 skill 时 agent 会 [具体失败行为]；装上后应当 [具体合规行为]。」

写不出这句 = 不知道要教什么 = 不做。

## 清单 B · 构建（Phase 3）

**frontmatter**（标注效力：【规范】＝开放标准硬性要求；【建议】＝官方推荐；【平台】＝平台上传/校验强制，规范无此条）
- [ ] 【规范】`name` 1–64 字符，仅小写字母/数字/单连字符，不首尾连字符，无 `--`，**与目录名完全一致**（注：本机校验器不查目录名一致性，别指望「装不上」兜底）
- [ ] 【建议】`name` 动名词优先（`creating-skills` 优于 `skill-creation`），避开 `helper`/`utils`/`tools`/`documents` 泛名
- [ ] 【平台】`name` 不含 `claude`/`anthropic` 保留字（仅上传市场时强制；官方自己因此改过名）
- [ ] 【规范】`description` 1–1024 字符、非空
- [ ] 【建议】`description` 第三人称，**只写触发条件 + 症状/同义词 + 排除项**
- [ ] 【建议】`description` **不总结工作流/步骤**（据 superpowers 实测，总结会让 agent 照它走捷径、跳过正文）
- [ ] 【平台】`description` 无尖括号 `<` `>`（本机校验器直接报错）
- [ ] 跨平台分发时 frontmatter 只留规范字段（`name`/`description` + 可选 `license`/`compatibility`/`metadata`/`allowed-tools`）；平台专属字段（version/author/description_zh 等）在打包时注入

**正文**
- [ ] <500 行、正文 token <5000；频繁加载型 <200 词，普通型 <500 词
- [ ] 开头 50 行内放「任务路由表/何时用」与最关键约束（会话压缩后只保留开头）
- [ ] 指令用祈使句；解释 why，不堆砌全大写 MUST/NEVER（纪律类除外）
- [ ] 关键校验交给脚本/确定性机制，不靠自然语言自律
- [ ] gotchas 只写反直觉项，不重复模型已知的 API 教程
- [ ] 形式匹配失败类型：禁令 / 正面配方 / REQUIRED 槽位 / 可观察谓词条件句（见 SKILL.md Phase 2）
- [ ] **效用三件套**（SkillLens 实证，单独就能把 better-rate 提到 64%+）：① 失败模式编码——已知失败路径显式写出，不是「别犯错」式叮嘱；② 可执行具体性——无「建议/可以考虑/根据情况/视情况而定」等模糊词；③ 高风险行动黑名单——rm / git reset --hard / force push 等破坏性操作显式列禁

**引用与资源**
- [ ] 引用**一层深**（SKILL.md → references/x.md，不再往下链）
- [ ] >100 行的 reference 顶部有目录（TOC）
- [ ] 需要 agent 读的文件，用强制祈使句点名：**STOP. 读 `references/x.md` 后再继续。**
- [ ] 脚本在正文中经解释器调用（`bash scripts/x.sh`、`python scripts/x.py`），**不裸路径调用**
- [ ] 脚本自包含或写明依赖；有可读错误；无交互输入；Windows 下不用 `.sh` 硬依赖
- [ ] 路径一律正斜杠相对路径，无绝对路径、无 symlink

## 清单 C · 验证（Phase 4，四道工序）

**1. 装得上**
- [ ] 平台校验器通过（如 `skills-ref validate ./my-skill`）
- [ ] **亲眼确认 skill 出现在可用清单里**（「已安装」≠「已启用且可见」——插件/symlink 场景会静默失效）
- [ ] 目标平台实测一次（Windows 与 Unix 若都涉及，各装一次）

**2. 触发对**
- [ ] 构造 10–20 条查询集：5–10 条 should-trigger（同一意图换措辞：正式/随意/不点名/拼写错误）+ 5–10 条 should-not-trigger，**优先 near-miss 负例**（共享关键词但实则该用别的 skill）
- [ ] 每条在**独立子 agent** 中跑，子 agent 提示不暗示目标 skill
- [ ] 判据：正例命中 5/5、负例泄漏 0/5、**跑两轮判定一致**
- [ ] 不用 description 原文当正例（那测的是字符串匹配，不是路由）
- [ ] 断言在观察真实输出之后再写；判结果不判路径

**3. 执行稳**
- [ ] ≥3 个真实任务 eval，**with-skill 与 baseline（无 skill 或旧版）成对跑**，看 delta 不看绝对值
- [ ] 断言可计数可验证（「输出含 ≥3 条具体建议」），不用精确短语匹配
- [ ] pass@k（能力）与 pass^k（稳定性）分开记
- [ ] 目标模型矩阵各测一遍（小模型可能需要更多细节，不能只在大模型上验）
- [ ] **评委铁律**：改与评分离（同一个 AI 又改又评＝无效，SkillLens 实证自评准确率仅 46.4%）；keep/revert 用 paired 同-judge 比较 + 奇数多数决；绝对分数只做 triage 不做裁决
- [ ] 下一轮换全新评委（防锚定）；「读起来更好」不作为保留理由（可读性与实际效用可能负相关）

**4. 不碍人**
- [ ] 与现存 skill 共存测试：新 skill 是否偷走了兄弟 skill 的触发
- [ ] 估算 description 长度对清单预算的占用（清单总预算约默认上下文 1%，超了会从最不常用的 skill 开始静默丢弃）

**安全（交付前必跑）**
- [ ] 静态扫描 9 类：硬编码秘密、下载即执行、编码后执行、注入句式、环境变量引用（需正当理由）、伪合规话术、HTML 注释或异常 unicode 藏内容、路径穿越、高危命令（具体检测模式串见 `scripts/skill_check.py`，本清单不枚举以免污染自检） <!-- audit:ignore DANGER_CMD 列举检测类别名称 --><!-- audit:ignore INJECTION 列举检测类别名称 --><!-- audit:ignore POLICY_LURE 列举检测类别名称 --><!-- audit:ignore PATH_TRAV 列举检测类别名称 -->
- [ ] **「读文件 + 联网」组合单独评审**（经典外泄链）
- [ ] 捆绑脚本逐行人工读过 + 沙箱试跑，行为与描述一致
- [ ] 外部 URL 逐个确认域名预期
- [ ] `allowed-tools` 最小化，禁裸 `Bash(*)`

## 清单 D · 发布与分发（Phase 5）

- [ ] 分发包排除安装产物（`_skillhub_meta.json`、`_knot_meta.json`、本地 `.claude/` 设置）
- [ ] 不用 `paths:`、`disable-model-invocation` 承载关键逻辑（这两个字段在部分平台/端有「整体消失」「完全不可发现」的实证故障）；约束意图写进 description 最可移植
- [ ] 平台专属字段按目标平台注入（WorkBuddy 市场需 description_zh/description_en/version/author；Codex/Gemini 只接受 name+description）
- [ ] `evals.json`（若建了）随包分发，模型更新后重跑防 regression
- [ ] 记录退役判据：baseline 通过率追平 skill 时，说明模型已追上，应下线而非继续维护

## 附：失败模式速查（触发 → 一线修复 → 兜底）

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| skill 从不触发 | description 补意图短语/领域词/症状词，关键词前置 | 建 10–20 条查询集实测触发率；确认查询本身有实质复杂度（简单一步查询不触发是设计使然） |
| 过度触发 | 加限定词与「NOT for X — use Y instead」负向边界 | 改用 hook 按文件类型确定性注入，或设为仅手动调用 |
| agent 不读 references | 引用改一层深；步骤末尾加强制祈使句；长文件加 TOC | 把必需内容直接内联进 SKILL.md（宁可正文长一点，也不要「写了但没人读」） |
| 「已安装」但不生效 | 用真实复制（`cp -r`）而非 symlink；确认已启用 | 换目录重装；查平台是否需显式 enable |
| 会话中途失效 | 关键规则移到 SKILL.md 顶部（压缩后只留开头） | 关键校验改脚本/hook 确定性执行 |
| Windows 上脚本跑不起来 | 正文用解释器调用；避免交互输入；路径正斜杠 | 提供 `.py` 而非 `.sh`，或声明 Git Bash 依赖 |
| 模型追平了 skill 的能力 | with/without 对比 eval 验证 delta；delta≈0 则下线 | 转为「团队流程编码型」skill（约定类不会过时） |
