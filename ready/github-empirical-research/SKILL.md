# GitHub 实证调研（三查流水线）

把"找东西 → 查实证 → 出裁定"固化成四段。源自 2026-10-09 至 10-12 的 11 次实战（记忆方案选型／学习资源／插件挑选／生态缝隙判断），已经用户验收。

## 适用范围（何时用）

- 选型：几个方案／库／工具，要选一个。
- 资源：找学习资料、找"大佬是怎么做的"。
- 插件／包：要装某个东西前，先摸清它是什么情况。
- 生态：判断某条赛道还有没有缝、谁已占位。

## 不适用范围（何时不用）

| 场景 | 该用什么 |
|---|---|
| 优化自己的 AI 配置（SOUL.md／自定义指令／MEMORY.md／规则文件） | `ai-config-upgrade`（它内部可调用本 skill 取实证） |
| 判断某个本地已装东西的行为 | 直接读本地代码／配置，不用联网 |
| 纯知识点问答 | 直接答 |

## 三条硬规则（违反即返工）

1. **先分诊通道，再拉数据**——连不上时第一反应是"查为什么"，不是"换镜像绕行"。把证书故障误判成被墙，会白走一整天。
2. **不凭直觉先给结论**——说"这里有缝／这个好"之前，必须附**占位者证据**（谁已在做、多大体量）。没有证据的直觉，标「直觉，待核」再输出。
3. **大输出先落盘，只把摘要提进对话**——几 MB 的 JSON／HTML 直接倒进对话＝污染上下文，且读不全。

## 四段流程

### 第 1 段 · 分诊通道（3 秒，省一天）

```bash
curl -s --ssl-no-revoke -o /dev/null -w "%{http_code}" https://api.github.com/
```

- 返回 `200` → 通道正常，直接走 API。
- 报错含 `CRYPT_E_NO_REVOCATION_CHECK` / `schannel` → **证书吊销检查故障，不是墙**。加 `--ssl-no-revoke` 即通（GitHub 全站适用）。
- `exit 7`／超时 → 才是真不通，走兜底：`https://codeload.github.com/<owner>/<repo>/zip/refs/heads/main` 直下 zip，或加镜像前缀 `https://ghproxy.net/<原链接>`。

### 第 2 段 · 三查（拉实证）

| 查什么 | 回答什么问题 | 怎么查 |
|---|---|---|
| **体量** | 有多少人在用 | GitHub：`stars`／`subscribers_count`；npm：周下载量 |
| **活跃** | 还活着吗 | GitHub：`pushed_at`（最近提交）；npm：`time.modified`／版本号与发布日期 |
| **形态** | 能不能用、怎么用 | 许可证（MIT／Apache-2.0／AGPL…）、安装方式、是否需常驻服务或 API key |

常用端点：

```bash
# GitHub 仓库搜索（按星排序）
curl -s --ssl-no-revoke "https://api.github.com/search/repositories?q=<关键词>&sort=stars&order=desc&per_page=20"

# npm 包元数据（版本／许可／更新时间）
curl -sL "https://registry.npmmirror.com/<包名>"

# npm 搜索
curl -sL "https://registry.npmmirror.com/-/v1/search?text=<关键词>&size=20"

# npm 周下载量（官方端点；若不通再试 npmmirror 的同名路径）
curl -sL "https://api.npmjs.org/downloads/point/last-week/<包名>"
```

### 第 3 段 · 落盘与摘要

1. 大响应先写盘（如 `tmp/gh/plugins.json`），加 `--compressed` 可显著提速（实测 5.4MB：超时 → 36 秒）。
2. 用脚本只提关键字段（名称／星数／最近更新／许可／一句话），摘要进对话，全文留磁盘。
3. 同会话不重复读同一文件，后续用路径引用。

### 第 4 段 · 出裁定

输出固定三件套：**对比表 → 一句话裁定 → 一个动作**。裁定要明确推荐项，不骑墙。

对比表列：名称 ／ 体量 ／ 最近更新 ／ 许可 ／ 形态 ／ 裁定（✅主推／🔶备选／❌排除）／ 排除理由。

## 附加两问（涉及"要不要用/做"时必答）

**一问：收费吗？** 三步收敛——① 包本身（公开包＋许可证文件）② 外联域名扫描（`grep -rhoE "https?://…" <包目录>`，排除文档与徽章引用）③ **是否触发模型调用**——只有调模型才真花钱；「显示价格／费用估算」≠ 收费。

**二问：谁已占位？** 说"这里有缝"之前，先拉同赛道已有实现（名称＋体量）。已被免费商品化（如官方注册表直接提供）或已有成熟占位者的，缝就不存在了。

## 输出模板

```
## 结论
一句话：选 X，因为 Y。

## 对比
（表）

## 一个动作
下一步具体做什么（含命令或路径）。

## 依据与时效
数据来源与采集时间；失效条件：什么信号出现时该推翻本结论。
```

## 反模式（交付前自检）

- ✗ 没跑分诊就断言"被墙了"。
- ✗ 凭"这个痛点很真"直接推荐方向（10-12 实证：凭直觉推的「静态扫描」缝，拉全 4,508 条注册表后被推翻）。
- ✗ 几 MB 输出直接倒进对话。
- ✗ 只给表不给裁定，或把决定权推回给用户。
- ✗ 引用星数／下载量却不带采集日期（这类数字 6 个月即需重查）。

## 来源与维护

- 提炼自 2026-10-09／10-11／10-12 共 11 次实战；通道分诊落自 10-12 的误判复盘。
- 失效条件：① 网络环境变化导致端点不可用 → 换端点并更新本文件；② GitHub／npm API 字段变更 → 以实际返回为准；③ 连续两周无调用 → 考虑并入 `ai-config-upgrade`，不单独维护。
