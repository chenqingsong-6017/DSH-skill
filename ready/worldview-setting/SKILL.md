# 世界观设定库（个人世界观 · 内容与逻辑分离）

管理陈青松（Cedar Chen）的个人世界观。**内容层** `content/` 七文件是信念唯一权威源；**逻辑层**（本文件）是调用、体检、更新协议，不随内容修改。

## 零、硬规则（先读，冲突按此裁定）

1. **不杜撰**：`content/` 里没有的信念不许替他补。缺了写「本库未记载」，不用常识或推断填坑。
2. **⏳ 只能本人解锁**：01_背景 人际观、05_价值观 失败观 转 ✅ 必须由他本人给结论；AI 只记素材、提候选问题。
3. **冲突优先级**：他的当场原话 ＞ 全局记忆 `~/.workbuddy/user-*/MEMORY.md` 里更晚的决策 ＞ 本库内容 ＞ 你的推断。本库与更晚决策冲突时**不得静默覆盖**——报冲突，等他裁定。
4. **数字即快照**：任何价格/日期/政策/薪资数字引用时带采集日期，超 6 个月先提示核查。
5. **本库是「他怎么想」，不是「他该怎么做」**：可引用条目支撑判断，不许以世界观名义替他下新决定。

## 一、调用方式

**触发**：提及「世界观／世界观设定／调用世界观／世界观体检／对账／更新世界观」，或手动挂载。

**命令统一在 skill 根目录执行**（`skills/worldview-setting`），下文不再重复。

**读取**：先读 `content/_index.md` 定位组件；再只读对应组件（01 背景／02 规则／03 角色／04 势力／05 价值观／06 目标），不全量读入。查历史读 `CHANGELOG.md`；对比旧版跑 `python scripts/maintain.py diff <备份目录名>`。

**出口形状**（引用信念必给四块，缺块即没交付）：

```
结论：<一句话>
依据：<组件 条目号> — <原文要点>
冲突/缺口：<矛盾或未记载；无则写「无」>
建议动作：<要更新／要体检／无需动作>
```

只引不改写；一个结论最多引 2 条依据。

## 二、更新协议（口令「更新世界观」）

1. **确认范围（提问式，2026-10-19 本人定）**：逐条候选改动各出一个提问卡片（`AskUserQuestion`），每题 2–4 个选项、每项写清「改成什么」而不是「是否同意」，我的推荐项排首位并标「推荐」；一个卡片最多 4 题，候选多于 4 条时分轮提问。他点选即视为裁定。**禁止把清单丢给他自由回复**。
   - 以下情形同样走提问，不开开放问题：定位不出组件、同一改动有多种落法、涉及 ⏳ 解锁、涉及 A／B 类冲突。
   - 选项不得伪造：真属于「只有他能答」的开放结论（如人际观、失败观的实质回答），只问「现在讨论／先收集素材」，不替他编选项。
   - 每题须带一行「为什么现在问」（一句话，指向哪条更晚决策或哪个冲突）。
2. **只改涉及条目**：`content/_index.md` 禁止手改（脚本重建）。悬置项按零·2。
3. **提交**：`python scripts/maintain.py commit "改动说明" --files 05_价值观.md --by "本人点选（提问式确认）" [--bump minor] --confirmed`
   - 不带 `--confirmed` 只演练。`--files` 与实际改动不一致时脚本拒绝提交——不猜。
   - `--bump` 缺省 patch；脚本检测到标题增删会提示，他说改 minor/major 才加参数。协议不替他定档。
   - 脚本自动：快照 → 比对实际改动 → 更新这些文件的 `updated` → 按 `--bump` 自增版本 → CHANGELOG → 重建注册表。
4. **同步导出物**：`python scripts/maintain.py export --out "D:/AI-date/workbuddy-date/记忆库/个人世界观框架_当前版.md"`
5. **报摘要**：版本号、改动条目（旧值 → 新值）、CHANGELOG 位置、受影响的未改条目。

## 三、体检协议（口令「世界观体检」／「对账」）

**触发**：他说体检／对账；或任一组件 `updated` 超 30 天（脚本逐文件告警，任一命中即算到期）；或他要据此做重大决定。

**第一步·跑脚本**（机械项不靠眼睛）：

```
python scripts/maintain.py audit
```

查：文件齐全 · meta 完整 · 版本与 CHANGELOG 一致 · 注册表与内容一致 · ⏳ 清单（一项＝一个含 ⏳ 的标题条目，标记次数不算项数）· 各组件 `updated` 滞后 30 天 · 采集日期超期 180 天 · 占位符。输出 FAIL／WARN／INFO。

**第二步·语义对账**（脚本查不了，不做只算半次体检）。体检必读六个组件全文（调用时可以按需读，体检不行）。对账对象固定两处，其他文件不算：

- 全局层：`C:\Users\cqs6017\.workbuddy\user-*\MEMORY.md`
- 详情层：`D:\AI-date\workbuddy-date\记忆库\AGENT.md` 与 `记忆库\memory-bank\*.md`（与全局层冲突时以全局层为准；详情层内部冲突也报，标 C）

| 检查 | 判据 | 分级 |
|---|---|---|
| 同一事实对账 | 两处数字/清单/日期/状态不一致（含「总量 vs 单项」口径不同但可推出矛盾的情形） | A |
| 定位漂移 | 被降级/封盘/换挡的东西仍写成当前主线 | B |
| 新增未入库 | 更晚决策里有、本库完全没有。「更晚」按条目写明的日期／版本判；措辞含「候选／待定／待拍板」的视为未定稿，不算决策 | D |
| 悬置项素材 | 按 01_背景、05_价值观 各自列出的问题判（两文件判据原文不同，以原文为准）。案例＝他本人的原话或直接行为记录，推断与二手转述不算；答不出写「未找到证据」 | D |
| 失效条件 | 判据写成「感觉」「看情况」，且拿不出他人可据此判对错的时间／数量／事件 | 记「处理建议」列，标「待改写」 |

**第三步·报告**：五列表 `| 检查项 | 结果 | 证据 | 冲突分级 | 处理建议 |`。证据带文件名＋章节/条目号；外部记忆没有编号的用「章节＋引文片段」。

分级（一条只取最高级，优先序 A > B > C > D）：**A 事实**（数字/清单/日期，及边界、状态这类可核对的事实性不一致）｜**B 定位**（路线/身份/取舍）｜**C 时效**（超期或详情层内部不一致）｜**D 缺口**（本库未记载，非矛盾）。

**A 类也只标不改**：在报告里写「本库待同步」＋最新值来源，不动 `content/`；要落库走二、更新协议。B 类一律等他裁定。**体检不改 `content/` 任何字节**；唯一允许的写入是他要存档的报告文件。

**报告去向**：默认只在对话里出；他要存档才写 `D:\AI-date\workbuddy-date\记忆库\世界观体检_YYYY-MM-DD.md`，不进 CHANGELOG。

**边界**：只读 `content/`、`CHANGELOG.md` 与上面两处记忆；`backup/` 是历史快照，不参与体检；`SOUL.md`／导出物／其他空间日志不在对账范围（需要时他明说）。本 skill 不含安全扫描流程。

## 四、增量与版本

- 以「条目」为单位增/改/删，不整文件重写；CHANGELOG 每条记「旧值 → 新值」。
- 语义化版本存于 `_index.md` 首行 meta：纯内容改 → patch；章节/编号结构改 → minor；框架重写 → major。脚本检测到标题增删会提示，定档由他决定（`--bump`）。
- 新条目必须带来源：〔毛〕〔马〕〔己〕或「本人确认 日期」。
- CHANGELOG 只追加，每条含版本/日期/改动/涉及文件/确认方式。**唯一的例外**：协议层（本文件与脚本）修订写「## 协议修订（日期，不计入内容版本）」，不占内容版本号，脚本正则也会跳过它。
- `backup/yyyyMMdd-HHmmss/` 每次 commit 自动快照。

## 五、回滚

`diff <备份目录名>` 看差异 → 编辑工具回填旧值 → `commit "回滚：..." --by 本人确认 --confirmed` → **跑一次 `export` 同步导出物**（回滚也是新版本，导出物不跟着变就与库不一致）。

## 维护脚本

`scripts/maintain.py` 纯标准库、无网络、无第三方依赖。命令：`status`／`audit`／`commit`／`diff`／`export`／`selftest`，用法见 `--help`。

## 诚实边界

- 本库只覆盖他明确表达过的信念；沉默不等于默认，缺项按「未记载」处理。
- 语义对账无法脚本化，漏检风险随内容增长上升——每次体检必须真读全局记忆，不能只看脚本绿的。
- 组件 `updated` 只反映该文件最后改动日，不代表内容已全部复核。
